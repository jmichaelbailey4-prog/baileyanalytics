# Distribution Phase — Design

**Date:** 2026-06-12
**Source:** audit findings in `2026-06-12-site-audit-and-next-steps.md` (top recommendation)
**Goal:** give the site its two missing loops — acquisition (shareable, findable) and retention
(subscribable) — by re-emitting the daily product the pipeline already composes (`today.json`)
into the channels where audiences live: email, link previews, search, and dated permalinks.

**Decisions signed off 2026-06-12:** Buttondown as the email service; daily email scheduled for
~7am ET (11:00 UTC); all four milestones in scope; brief.html becomes fully pipeline-baked
(Michael delegated the architecture call — rationale in §2).

---

## 0. Shape of the change

Four independently-shippable milestones on one branch. Everything follows the existing
pipeline conventions: **pure renderer modules in `scripts/lenses/`** (no network, no disk I/O),
**`refresh_lenses.py` owns I/O**, **`unittest` + fixtures for every new module**, additive and
fault-tolerant (a failure in any new emitter keeps prior output and never breaks the brief).

New third-party dependency: **Pillow** (pinned in `requirements.txt`) for og-card rendering.
New font asset: **Inter** (Regular + SemiBold TTFs) under `assets/fonts/` with its OFL license
file, so Actions runners render cards deterministically.

```
today.json ──┬─→ briefpage.py ──→ dashboards/brief.html            (baked, replaces JS render)
             │                 ──→ dashboards/brief/YYYY-MM-DD.html (archive permalink)
             │                 ──→ dashboards/brief/index.html      (archive listing)
             ├─→ ogcard.py    ──→ og/brief-YYYY-MM-DD.png           (link-preview card)
             ├─→ digest.py    ──→ send_digest.py ──→ Buttondown API (daily email)
             └─→ feed.py      ──→ feed.xml                          (existing, unchanged)
archive manifest + config.CATEGORIES ──→ sitemap.py ──→ sitemap.xml
lens JSON ──→ staticread.py ──→ marked block patched into each lens page
```

**Publication-day rule:** archive page, og card, and email are emitted only on days the brief's
content actually changed (the existing `wrote` flag from `build.write_lens_file`). Quiet days
(some weekends) produce nothing: no duplicate-content archive pages, no empty emails, and the
13:00 UTC backup cron naturally no-ops. The archive manifest is the source of truth for "was
today a publication day," which is what makes the email send idempotent across reruns.

## 1. Milestone A — SEO statics

One-time edits plus two small generators. No behavior change to any page.

- **Canonical tags:** self-referential absolute `<link rel="canonical">` on every HTML page
  (33 lenses, 8 hubs, home, about, brief, track-record, dashboards hub, archive template).
- **og:image + twitter:card:** every page gets `og:image` and `twitter:card =
  summary_large_image`. Brief + archive pages reference the dated daily card (§3); all other
  pages reference a one-time static brand card `og/site.png` (generated by `ogcard.py`,
  committed once).
- **JSON-LD:** `WebSite` + `Organization` on home; `NewsArticle` (headline = verdict sentence,
  `datePublished`) on brief/archive pages (emitted by the baked renderer); static
  `BreadcrumbList` on lens pages. Nothing else — no schema theater.
- **robots.txt:** repo-owned, allow-all, with a `Sitemap:` pointer. *Post-deploy check:*
  Cloudflare currently serves its managed content-signals robots.txt; verify it prepends to
  (not replaces) the origin file once ours exists.
- **sitemap.xml:** new pure module `lenses/sitemap.py` — inputs are the static page list,
  `config.CATEGORIES` (hub + lens hrefs), and the archive manifest; output is sitemap XML.
  Written at repo root during the `--brief` pass (it must grow as archive pages accrue).
  `lastmod` only where honest: brief = `generated_at`, archive pages = their date; omitted for
  hand-edited pages.
- **404.html:** branded, standalone inline CSS (same convention as home/about), links to the
  brief, dashboards hub, and home. GitHub Pages serves it automatically.
- **Receipts:** GitHub repo link on About ("built in the open") and on Track Record where the
  ledger/verifiability claim is made (link to the repo and to `data/predictions/`).

Out of scope here (tracked as a separate quick-wins sweep): hub `h1` badge concatenation,
home stat-color semantics, axe findings, Track Record open-predictions display.

## 2. Milestone B — Baked brief, archive permalinks, og cards

**`lenses/briefpage.py`** (pure): renders `today.json` → a complete static brief HTML page.
Parameterized for two consumers:

- **`dashboards/brief.html`** — today's render. Replaces the current client-side fetch+render
  entirely; the ~100-line inline script in brief.html is deleted, not duplicated. The page
  keeps its URL, nav, styles (`lens.css` + existing inline block), section structure, and
  deep-link anchors (`#alert` etc. — which now work natively since no section starts hidden).
  Canonical stays `/dashboards/brief.html`; og:image points at today's dated card; `NewsArticle`
  JSON-LD embedded. An "Archive →" link lands beside the as-of stamp.
- **`dashboards/brief/YYYY-MM-DD.html`** — the same render with an archive banner ("This is
  the brief from June 12, 2026 — see today's brief"), prev/next-day links, canonical to its own
  dated URL, and the dated og card. Append-only, one per publication day.

Why baked wins long-term (decision rationale): one renderer instead of a JS/Python sync pair
(the `_fmt`/`fmtVal` trap, avoided); the flagship page becomes testable in the existing
`unittest` suite; live page and archive are provably identical; and any future mobile app
consumes `today.json` as its API regardless — HTML is just one renderer over the data layer.
Failure mode: a bake failure leaves yesterday's committed page in place (the guard already
ensures no partial writes), which is the same degradation the JS version had.

**`dashboards/brief/index.html`** — archive listing, regenerated each publication day from the
manifest: entries grouped by month, each row = date + verdict badge + counts phrase.

**Archive manifest** — `data/brief/_archive_index.json`, append-only:
`[{date, status, counts_phrase, sentence}]`. Drives the archive index, sitemap growth, and the
email send decision.

**`lenses/ogcard.py`** (pure: returns PNG bytes): Pillow-drawn 1200×630 card matching the
site's dark visual language — wordmark, date, status badge pill in its status color, verdict
sentence wrapped to ≤4 lines, `baileyanalytics.com` footer. Output `og/brief-YYYY-MM-DD.png`
(~50–80 KB/day ≈ 20 MB/yr — fine). Also generates the one-time `og/site.png` brand card via a
`--site-card` entry point. Card failure is isolated: the page falls back to `og/site.png` and
the run continues.

**`brief.js` survives untouched** for its two remaining consumers: the home counts strip
(`compact:true`) and home hero verdict line (`mode:"line"`).

**Home page** (`index.html`): hero verdict sentence additionally baked as static text in the
HTML (crawlers see it; `brief.js` refreshes it client-side as today), and og:image repointed at
the dated daily card — both via the same marker-patch mechanism milestone D uses for lens pages
(marked regions, content-aware rewrite). Home thereby joins the machine-committed surface.

## 3. Milestone C — Email digest + subscribe

**`lenses/digest.py`** (pure): `today.json` + date → `{subject, html}`.

- **Subject:** transition-led when transitions exist ("Electricity tips to WATCH — Today's
  Brief, Jun 12"); otherwise the counts phrase ("Today's Brief — 3 alert · 8 elevated · 3 on
  watch, Jun 12"). The date token in the subject is also the idempotency key.
- **Body:** email-safe HTML — tables, inline styles, **light theme** (email-client norm; the
  dark site palette is unreliable across clients). Order: wordmark → date → verdict (badge +
  sentence) → what changed (transitions, else top movers, ≤5 items) → watching next (≤3) →
  one-line pressure summary linking to the brief's pressure section → footer (permalink to
  today's archive page, "built from public data" line, Buttondown's unsubscribe variable).
  Every link absolute. Text-first, no images (no og card embed — keeps it fast and
  spam-score clean).

**`scripts/send_digest.py`** (CLI, owns network + decisions):

1. Exit 0 quietly when `BUTTONDOWN_API_KEY` is unset (forks, local runs).
2. Read the archive manifest: if today's date isn't a publication day, exit (quiet day).
3. Query Buttondown (`GET /v1/emails`, recent page) for an email whose subject carries today's
   date token: if found, exit (already sent — reruns and the backup cron are safe).
4. `POST /v1/emails` with the digest, scheduled for `max(now, 11:00 UTC)` — ~7am ET on the
   normal run, immediate on a late backup-cron catch-up.
5. `--dry-run` prints subject + HTML to stdout, no network.

**Workflow:** new step in `refresh-fred.yml` after the brief rebuild and before the commit step
(`if: success() || failure()`, `BUTTONDOWN_API_KEY` secret). Commit-step globs extended:
`data/ feed.xml sitemap.xml og/ dashboards/ index.html` (home is patched daily too — §2).

**Subscribe form** (Buttondown embed — plain HTML form POST, no JS): on the brief (under the
verdict section — primary placement), home (band between the tiles and "View all dashboards"),
and About (Get in touch block). Copy reflects the honest cadence: *"Get Today's Brief in your
inbox — free, every morning the board changes."* Form styling matches each page's conventions
(lens.css class for brief; inline CSS for home/about per the shared-chrome gotcha).

**Alternative considered — self-managed sending via the Cloudflare domain (deferred):**
Cloudflare Email Routing is receive-only; self-managing the digest would require a
transactional sender (SES/Resend) plus a Workers + D1 backend for subscribe/double-opt-in/
unsubscribe/bounce handling, and ongoing deliverability ownership — a product in itself, built
for zero subscribers. The migration path is staged instead: (1) launch on free Buttondown;
(2) at traction, Buttondown's custom sending domain (~$9/mo) puts baileyanalytics.com on the
from-line via DKIM records in Cloudflare DNS; (3) full self-hosting later is one-file swap —
`send_digest.py` is the only ESP-aware code, and Buttondown's subscriber list exports as CSV.

**Michael's setup checklist (one-time, before merge):** create the Buttondown account
(username lands in the form action URL), enable double opt-in, set reply-to to
michael@baileyanalytics.com, add `BUTTONDOWN_API_KEY` to Actions secrets. Post-launch:
verify Cloudflare robots.txt behavior (§1) and submit the sitemap in Google Search Console.

## 4. Milestone D — Lens-page static reads (last; cuttable)

**`lenses/staticread.py`** (pure): lens JSON → an HTML fragment — headline read as text, the
scoreboard key stats (label + formatted value + as-of), and each indicator's read paragraph.
Unit formatting reuses `build._fmt` (the Python side of the existing fmt pair; no new logic).

**Patcher** (in `refresh_lenses.py`, per category pass): each lens page gains a marked region —
`<!-- baked-read:start --><section id="baked-read">…</section><!-- baked-read:end -->` —
replaced in place only when the rendered fragment differs (content-aware, same spirit as
`write_lens_file`; no churn on quiet days). `lens.js` removes `#baked-read` once the
interactive render succeeds — crawlers and no-JS readers see the content, JS users see charts.

Risk note: the pipeline now patches committed HTML, so `dashboards/` joins the
machine-commits-to-main surface (the existing pull-before-push / take-newer-side convention in
CLAUDE.md extends to it). Markers keep patches surgical. If this milestone fights the workflow
in practice, it ships separately — A–C don't depend on it.

## 5. Testing

`unittest` + fixtures, TDD per the repo norm:

- `test_briefpage.py` — full render from the brief fixture: all sections present, archive
  banner/prev-next only on archive variant, anchors, JSON-LD block, escaping of user-visible
  strings.
- `test_digest.py` — subject selection (transition-led vs counts), date token, HTML contains
  verdict/permalink/unsubscribe variable, ≤5 movers cap, quiet-day inputs.
- `test_ogcard.py` — returns valid PNG bytes at 1200×630; long verdict wraps without overflow
  (smoke via Pillow re-open).
- `test_sitemap.py` — includes all lens/hub/static pages + manifest archive entries; valid XML;
  honest lastmod rules.
- `test_staticread.py` — fragment from a lens fixture; formatting parity with `build._fmt`.
- `test_send_digest.py` — decision logic (no key / not a publication day / already sent /
  schedule time) with the API mocked; `--dry-run` output.
- Existing `test_feed.py` / brief tests unchanged — `feed.py`, `today.py`, `state.py` are not
  modified.

`--dry-run` of `refresh_lenses.py` exercises the new emitters from fixtures (and now also
overwrites `dashboards/brief.html` + archive output — the existing dry-run warning in CLAUDE.md
covers it; extend the wording there).

## 6. Out of scope

The quick-wins sweep (Track Record open predictions, counts-strip link, stat-color semantics,
hub `h1` fix, axe items, `market-scoreboard.json` thinning), the synthesis/"why" layer, PWA
manifest/push, social accounts, and any new data sources. Each is deliberately deferred — see
the audit doc's ranking.

## 7. Delivery

Per the standing workflow: this spec → sign-off → implementation plan (`writing-plans`) →
feature branch → `/code-review` gate → merge/push only on Michael's go. Milestones land in
order A → B → C → D; each leaves the site shippable. The natural deadline: first prediction
grades land within weeks — subscribe and share mechanics should be live before that story
breaks.
